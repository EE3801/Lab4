# Part 1. Update files from GitHub 

## 1.
We will first push to GitHub the pipeline-slurm.sh script you created in Lab 3. You will need to:
- first create a cluster
- ssh to the cluster
- initialize conda
- activate the env1 environment

After that you can do:

> [Headnode]
>```shell
>cd /data/src/PyHipp
>```

Create a personal access token (Classic) to use with GitHub [here](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/creating-a-personal-access-token) (scroll down to find the section titled "Creating a personal access token (classic)"). Set the expiration date to 3 months and select "repo" for the scope. After the token is generated, copy the token to a safe place as you will need it later.

Check your repository configuration:

> [Headnode & in PyHipp directory]
>```shell
>git remote -v
>```

which should return:

```shell
origin		https://github.com/yourusername/PyHipp.git (fetch)
origin		https://github.com/yourusername/PyHipp.git (push)
upstream	https://github.com/shihchengyen/PyHipp.git (fetch)
upstream	https://github.com/shihchengyen/PyHipp.git (push)
```

Do the following to switch your PyHipp directory to use your token (replace xxxx with your token):

> [Headnode & in PyHipp directory]
>```shell
>git remote set-url origin https://xxxx@github.com/yourusername/PyHipp.git
>```

If you accidentally cloned the wrong repository in Lab 3 (i.e. shihchengyen/PyHipp instead of your_username/PyHipp), you can reset it by running the command above.

Add the upstream repository if you do not see the output above:

> [Headnode & in PyHipp directory]
>```shell
>git remote add upstream https://github.com:shihchengyen/PyHipp.git
>```

Repeat the "git remote -v" command above to check that the upstream repositories have been set properly.

In order to avoid creating a conflict between your version of pipeline-slurm.sh and requirements.txt and the ones in the upstream repository, rename your files by doing:

>> [Headnode & in PyHipp directory]
>```shell
>mv pipeline-slurm.sh mypipeline-slurm.sh
>mv requirements.txt myrequirements.txt
>```

## 2.
Now you are ready to merge with the upstream changes:

> [Headnode & in PyHipp directory]
>```shell
>git fetch upstream
>
>git checkout main
>
>git merge upstream/main
>```

This should add two files named "consol_jobs.sh" and “ec2snapshot.sh” in addition to the 2 files mentioned above. You can push the merged changes to your forked repository by doing:

> [Headnode & in PyHipp directory]
>```shell
>git push
>```

You can add the renamed files to your GitHub repository by doing:

> [Headnode & in PyHipp directory]
>```shell
>git add mypipeline-slurm.sh myrequirements.txt
>
>git config --global core.editor "nano"
>
>git commit
>```

At this point, a nano editor window will open up for you to add a commit message. It is good practice to add a concise description of what changes were made in the nano window so in the future, you can look back and understand what was done. Once you are done, you can exit nano the usual way, making sure to save the file with the suggested filename. After that, you can push the scripts to your GitHub repository by doing:

> [Headnode & in PyHipp directory]
>```shell
>git push
>```

Update your snapshot using another Terminal window so the changes are saved for use later in this lab.
